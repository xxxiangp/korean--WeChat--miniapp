## 一、总体方案

**微信小程序原生开发 + 微信云开发（全栈）**

选型理由：

| 维度 | 说明 |
|------|------|
| 复杂度 | 零额外框架，无编译链路，开箱即用 |
| 包体 | 无框架 runtime 开销，天然满足主包 < 2MB |
| 后端 | 云开发免运维、免部署，一人可搞定全栈 |
| 迭代 | 官方文档完善，调试工具成熟，改了就能发 |
| 扩展 | 未来若需跨端，可渐进迁移至 uni-app，成本可控 |

---

## 二、前端（小程序端）

| 层面 | 选型 | 说明 |
|------|------|------|
| 框架 | 微信小程序原生 | WXML + WXSS + JS/TS，无需 Taro/uni-app |
| 语言 | TypeScript | 类型安全，SRS 算法逻辑不易出错 |
| 样式 | WXSS + CSS 变量 | 主题色通过 CSS 变量全局管理 |
| 状态管理 | MobX-miniprogram | 官方推荐，轻量，管理用户数据/学习状态 |
| 动画 | lottie-miniprogram | 结算页庆祝动画 |
| 音频 | wx.createInnerAudioContext | 原生 API，播放云存储中的 TTS 音频 |

### 目录结构建议

```
miniprogram/
├── pages/             # 页面
│   ├── index/         # 单词首页
│   ├── learn/         # 背单词页
│   ├── review/        # 复习页（复用 learn 组件）
│   ├── result/        # 结算页
│   ├── stats/         # 统计页
│   ├── mine/          # 我的页面
│   └── book/          # 选词书页
├── components/        # 公共组件
│   ├── quiz-card/     # 四选一卡片
│   ├── recall-card/   # 主动回忆卡片
│   └── word-detail/   # 答案揭示详情
├── services/          # 业务逻辑层
│   ├── srs.ts         # SRS 算法
│   ├── queue.ts       # 会话内队列管理
│   └── storage.ts     # 本地缓存 + 云同步
├── store/             # MobX 状态
├── utils/             # 工具函数
└── static/            # 本地静态资源（Lottie JSON 等）
```

## 三、后端（微信云开发）

| 服务 | 用途 | 说明 |
|------|------|------|
| 云数据库 | 用户数据持久化 | NoSQL，存用户学习记录、全局数据、积分 |
| 云函数 | 服务端逻辑 | 积分计算、数据校验、定时任务（如每日重置） |
| 云存储 | 音频文件 | 1624 词 × TTS 音频，按级别目录存放 |

### 数据库集合设计

| 集合 | 存储内容 | 对应 PRD |
|------|----------|----------|
| users | 用户全局数据 | 10.3 节 |
| word_records | 单词学习记录（SRS 参数） | 10.2 节 |
| checkins | 签到记录 | 七章 3）|

### 云函数清单（MVP）

| 函数名 | 职责 |
|--------|------|
| onLogin | 首次登录初始化用户数据 |
| syncProgress | 批量同步一组学习结果 |
| dailyReset | 定时触发器，每日 00:00 重置今日标记 |

## 四、词库数据方案

| 策略 | 说明 |
|------|------|
| 词库 JSON | 放入小程序分包，本地直接读取，无网也能学 |
| Quiz 干扰项 | 同上，随词库分包加载 |
| 分包规划 | 主包（页面 + 逻辑）< 2MB；词库分包（JSON + 少量资源）独立加载 |

---

## 五、离线与同步策略

```
用户学习 → 数据先写本地缓存（wx.setStorage）
         → 一组完成后调用 syncProgress 云函数上报
         → 下次打开 App 时拉取云端最新数据覆盖本地
         → 无网时正常学习，联网后自动同步
```

冲突处理：以云端 last_reviewed 时间戳较新的记录为准。

## 八、技术风险与应对

| 风险 | 应对 |
|------|------|
| 云数据库免费额度不够 | MVP 阶段完全够用（50000次/日读写）；用户量起来后按量付费 |
| 音频文件流量费 | 首次播放后本地缓存，重复播放不消耗流量 |
| 小程序审核不过 | 内容合规（词汇为公开语言事实），不涉及 UGC |
| TypeScript 编译 | 微信开发者工具原生支持 TS，零配置 |
