## 阶段一：项目初始化与基础架构

### 步骤 1.1 — 创建微信小程序项目骨架

**指令：** 使用微信开发者工具创建一个新的小程序项目，选择 TypeScript 模板。项目名称为「韩语背单词」。创建后清理模板默认页面内容，只保留空白框架。

**目录结构要求：**
- `miniprogram/pages/` 下创建 7 个空页面目录：index、learn、review、result、stats、mine、book
- `miniprogram/components/` 下创建 3 个空组件目录：quiz-card、recall-card、word-detail
- `miniprogram/services/` 目录（空）
- `miniprogram/store/` 目录（空）
- `miniprogram/utils/` 目录（空）
- `miniprogram/static/` 目录（空）

**验证：**
1. 微信开发者工具编译无报错
2. 模拟器中能看到空白页面
3. 所有目录存在且结构正确
4. `project.config.json` 中 appid 字段已填入（可用测试号）

## 阶段二：数据层与状态管理

**指令：** 在 `services/` 下创建词库加载模块。实现以下功能：根据级别名称（beginner/intermediate/advanced）加载对应词库 JSON 和 quiz JSON；返回完整的词汇数组和对应干扰项数组；提供按 ID 查询单个词的方法。所有数据加载完成后缓存在内存中，避免重复读取文件。

**验证：**
1. 调用加载初级词库方法，返回数组长度为 1018
2. 调用加载中级词库方法，返回数组长度为 336
3. 调用加载高级词库方法，返回数组长度为 270
4. 通过 ID 查询某个词，返回结果包含 korean、pronunciation、pos、pos_cn、meaning 字段
5. 查询同一个词的 quiz 数据，返回 3 个干扰项
6. 连续调用两次加载，第二次直接使用缓存（不重新读文件）

**验证：**
1. 存入一条学习记录后能正确读取
2. 存入用户全局数据后能正确读取
3. 清除操作后对应数据为空
4. 存入 3 条记录（1 条到期、1 条未到期、1 条已移除），获取到期词方法只返回 1 条
5. 小程序重启后存储数据仍存在

### 步骤 2.3 — 安装与配置 MobX 状态管理

**指令：** 通过 npm 安装 `mobx-miniprogram` 和 `mobx-miniprogram-bindings`。在 `store/` 下创建全局 Store，包含以下可观察状态：当前词书级别、当前学习位置（各级别独立）、今日学习词数、今日学习时长（分钟）、今日是否已完成首次背词、今日是否已完成首次复习、用户积分。提供修改这些状态的 action 方法。

**验证：**
1. npm 构建成功，无报错
2. 在页面中通过 `storeBindingsBehavior` 能正确绑定状态
3. 修改 Store 中某个状态值，绑定页面的 data 自动更新
4. 多个页面绑定同一状态，一处修改全部同步

---

### 步骤 2.4 — 实现 SRS 算法模块

**指令：** 在 `services/` 下创建 SRS 算法模块。根据 `背诵机制设计.md` 中的规则实现以下纯函数：

- 背新词 SRS 初始化：接收通过方式（首次通过/重学通过/5次未通过），返回 interval、ease、due_date
- 复习 SRS 更新：接收当前 interval、ease 和通过方式（首次通过/重学通过/5次未通过），返回新的 interval、ease、due_date
- ease 约束：下限 1.3，上限 3.0
- interval 计算后向上取整为整数天

**验证：**
1. 背新词首次通过 → interval=1, ease=2.5, due_date=明天
2. 背新词重学通过 → interval=1, ease=2.3, due_date=明天
3. 背新词 5 次未通过 → interval=1, ease=1.3, due_date=明天, is_difficult=true
4. 复习首次通过（当前 interval=4, ease=2.5）→ interval=10, ease=2.5
5. 复习重学通过（当前 interval=4, ease=2.5）→ interval=5, ease=2.4
6. 复习 5 次未通过（当前 interval=4, ease=2.5）→ interval=1, ease=2.3
7. ease 不会低于 1.3，不会高于 3.0
8. interval 结果为整数（如 4×1.2=4.8 → 取整为 5）

---

### 步骤 2.5 — 实现会话内队列管理模块

**指令：** 在 `services/` 下创建队列管理模块。管理一次学习/复习会话内的单词队列，实现以下功能：

- 初始化队列：接收一组词 ID 列表，设置当前指针为 0
- 获取当前词：返回当前指针位置的词 ID 及其应展示的页面类型（四选一 / 主动回忆）
- 完成当前词（通过）：指针前进，该词不再出现
- 未通过当前词：将该词插入当前位置后 3~5 个词的位置；记录该词的重现次数；若重现次数达到 5 次则标记为困难词并不再插入
- 标记「熟」：移除该词，指针前进
- 判断会话是否结束：队列为空或所有词已处理

**关于页面类型的判断规则：**
- 新词首次出现 → 四选一
- 四选一阶段失败（选错/不太记得）→ 重现时还是四选一
- 四选一通过后紧接 → 主动回忆
- 主动回忆点模糊 → 重现时直接展示主动回忆
- 主动回忆点忘记 → 重现时退回四选一

**验证：**
1. 初始化 10 个词，逐一通过，共取出 10 次后会话结束
2. 第 3 个词未通过，验证它被插入到第 6~8 个位置之间
3. 同一个词失败 5 次后不再被插入队列，标记为困难词
4. 四选一选错后重现，页面类型为四选一
5. 主动回忆点模糊后重现，页面类型为主动回忆
6. 主动回忆点忘记后重现，页面类型为四选一
7. 全部标记「熟」后会话立即结束
8. 队列中多个词同时未通过时，按失败先后顺序依次插入

### 步骤 3.5 — 串联背单词完整流程

## 阶段四：复习模块

### 步骤 4.1 — 实现复习队列生成逻辑

**指令：** 创建复习队列生成功能：从本地存储中读取当前级别的所有学习记录，筛选出到期词（due_date ≤ 今天且 is_removed=false），按以下优先级排序：

1. 困难词（is_difficult=true 或 ease < 1.8）排最前
2. 逾期词（due_date < 今天），欠债天数越多越靠前
3. 今日到期词（due_date = 今天）

若到期词数量超过用户设置的每组数量，按优先级截取前 N 个。

**验证：**
1. 存入 5 条记录（2 条到期、2 条未到期、1 条已移除），获取到期队列长度为 2
2. 困难词排在普通到期词前面
3. 逾期 3 天的词排在逾期 1 天的词前面
4. 若到期 15 词、每组 10 词，只返回前 10 个
5. 无到期词时返回空数组

3. 复习交互与背新词完全一致（四选一→主动回忆流程）

### 步骤 4.3 — 实现复习完成后的 SRS 更新

**指令：** 复习一组完成后，对每个词执行 SRS 更新（调用 SRS 模块的复习更新函数）：

- 首次通过：interval = 旧 interval × ease，ease 不变

**指令：** 对全部页面进行视觉检查与细节打磨：

- 检查所有页面在 iPhone SE（小屏）、iPhone 14（标准）、iPhone 14 Pro Max（大屏）三种机型上的布局适配
- 确保首页和统计页在所有机型上一屏展示（不出现滚动）
- 检查按钮点击态（有按下反馈，如透明度变化或缩放）
- 检查所有可点击元素有足够的点击区域（最小 44×44pt）
- 检查文字对比度满足可读性（主文字与背景对比度 ≥ 4.5:1）
- 检查深色模式下的显示（如不支持则明确标注）

**验证：**
1. 3 种机型下页面均无溢出、截断、重叠
2. 首页和统计页在小屏上仍然一屏完整展示
3. 所有按钮有点击反馈
4. 无过小的可点击区域
5. 文字清晰可读

### 步骤 8.10 — 主包体积检查与优化

**指令：** 在微信开发者工具中查看代码包分析，确保：

- 主包 < 2MB

**验证：**
1. 主包体积 < 2MB
2. 分包体积合理（词库 JSON 约 500KB~1MB）
3. 代码包分析中无明显的大体积冗余文件
4. 预览/上传时无体积警告
